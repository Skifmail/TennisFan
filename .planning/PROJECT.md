# PROJECT: Клубный раздел теннисной платформы TennisFan

## Что это

**Клубный раздел** — новый модуль платформы TennisFan (Tennison), позволяющий теннисным клубам регистрироваться на платформе по подписке (Старт / Базовый / Про), приглашать игроков, проводить турниры с клубным рейтингом и собирать членские взносы через собственный платёжный аккаунт (ЮKassa/Stripe). Игроки получают единый личный кабинет с контекстом клуба: турниры клуба, рейтинг клуба, взносы и приглашения.

Один лайнер: *Регистрация клубов по подписке, управление игроками и турнирами, рейтинг и взносы с интеграцией в существующую платформу.*

---

## Ценность

- **Для клубов**: отдельный «кабинет» на платформе, приглашение игроков по ссылкам, турниры с привязкой к клубу, рейтинг участников, настройка и сбор членских взносов (деньги идут на счёт клуба в ЮKassa/Stripe).
- **Для игроков**: один аккаунт платформы, переключение контекста между клубами, запись на клубные турниры, просмотр рейтинга и оплата взносов в ЛК.
- **Для платформы**: монетизация подпиской клубов (тарифы Старт/Базовый/Про), расширение аудитории без дублирования аккаунтов.

---

## Требования (высокоуровнево)

Источник: спецификация `club_dev_spec.docx` (март 2026).

### 1. Регистрация и онбординг клуба

- Стартовый экран выбора типа аккаунта: «Я игрок» / «Я представляю клуб».
- Регистрация клуба в 3 шага: данные клуба (название, город, адрес, контакты, логотип, ФИО ответственного) → выбор тарифа (Старт/Базовый/Про, помесячно/ежегодно) → оплата или trial 14 дней (только Старт).
- После активации: создание клуба, подписки, записи в `club_members` (текущий пользователь = admin), редирект в `/club/dashboard`.

### 2. Игроки клуба

- Публичная страница клуба `/club/{slug}` (только при `is_public`, тарифы Базовый/Про).
- Инвайт-ссылки: генерация, срок действия, лимит использований; флоу вступления по токену (`/club/{slug}/join?token=...`).
- Добавление игрока админом: поиск по email (существующие пользователи платформы), приглашение по email; импорт CSV.
- В ЛК игрока — блок «Входящие приглашения» (принять/отклонить).

### 3. Личный кабинет игрока клуба

- Шапка ЛК с клубным контекстом: логотип, название клуба, переключатель клубов (если несколько), статус членского взноса (оплачен/не оплачен/истекает).
- Разделы: «Мои турниры» (фильтры, запись, результаты), «Рейтинг клуба» (место, очки, таблица, график), «Членский взнос» (если включён клубом: статус, оплата, история).

### 4. Панель управления клубом (admin/manager)

- URL: `/club/dashboard`. Роли: admin (полный доступ), manager (ограниченный: игроки, турниры, рейтинги, приглашения; без финансов и настроек).
- Разделы: Дашборд (статистика, лента событий, быстрые действия), Игроки (поиск, фильтры, добавление, импорт/экспорт, профиль, исключение), Турниры (создание с клубным контекстом, лимиты по тарифу, ввод результатов), Рейтинги (таблица, экспорт PDF/Excel), Взносы (настройка, мониторинг оплат, ручная отметка, напоминания, подключение ЮKassa/Stripe), Приглашения (ссылки, QR), Менеджеры (назначение, права), Настройки клуба, Подписка (тариф, продление, история).

### 5. Финансы

- Подписка клуба платформе: тарифы Старт/Базовый/Про, период месячный/годовой; webhook от платёжной системы для обновления статуса.
- Членские взносы игроков: настройка в клубе (сумма, период, день начала, блокировка доступа к турнирам); оплата через аккаунт клуба в ЮKassa/Stripe; webhook → запись в `club_fee_payments`; ручная отметка «оплачено» админом.

### 6. Уведомления

- Триггеры: приглашение в клуб, напоминание/просрочка взноса, взнос оплачен, турнир (напоминания, результаты), изменение рейтинга, новый игрок в клубе (для админа), сводка должников, истекает подписка клуба. Каналы: Email и Telegram (существующий бот платформы). Настройки уведомлений в ЛК и в панели клуба.

### 7. Межклубные турниры (заготовка)

- В `tournaments`: поля `club_id` (nullable), `is_open_interclub` (только Про). Таблица `club_tournament_applications` для заявок клуба на участие. Базовый UI: чекбокс «Открытый межклубный» в форме турнира, кнопка «Подать заявку» на странице турнира, раздел «Межклубные заявки» в панели организатора.

### 8. Admin платформы (владелец)

- Раздел «Клубы» в Django Admin (или отдельная панель): список клубов (фильтры, блокировка, смена тарифа, удаление), детальная страница клуба (профиль, подписка, игроки, турниры, взносы, рейтинги, приглашения, лог действий), управление тарифами платформы (Старт/Базовый/Про — лимиты, цены), финансовая сводка по подпискам, глобальные настройки (trial, хранение данных после истечения, автоудаление suspended, регистрация новых клубов). Аудит: `platform_audit_log` для действий platform_admin.

### 9. Клубные тарифы для игроков (раздел 10 спецификации)

- Клуб может создавать свои тарифы для игроков (Юниор, Взрослый, VIP и т.д.) — независимо от тарифа подписки платформы. Таблицы: `club_plans`, `club_member_plans`, `club_plan_tournament_access`, `club_plan_slot_usage`. Лимиты: макс. турниров в месяц, слоты на многодневные турниры, несгораемые слоты; ограниченный доступ к турнирам по тарифу. Выбор тарифа при вступлении; смена тарифа в ЛК (если разрешено). Управление тарифами в панели клуба: `/club/dashboard/plans`.

## Ограничения и допущения

- **Интеграция**: используем существующие модели `users.User`, `tournaments.Tournament` и др.; расширяем, не ломая текущие сценарии. Добавляем `club_id` (nullable) и `is_open_interclub` в турниры.
- **Платежи**: подписка клуба — через текущую или отдельную интеграцию платформы с ЮKassa; взносы игроков — через аккаунт клуба (Shop ID + Secret Key клуба), платформа только инициирует платёж и обрабатывает webhook. Secret Key хранить зашифрованным.
- **Права**: разграничение admin / manager клуба; platform_admin — только владелец платформы (staff/superuser или отдельный флаг).
- **Лимиты тарифов**: проверка лимитов (игроки, турниры в месяц, менеджеры) через middleware/service (ClubPlanGuard); при превышении — 403 с кодом (PLAN_LIMIT_EXCEEDED и т.д.).
- **Статусы клуба**: trial → active → suspended (после истечения подписки, данные хранятся 30 дней) → deleted (автоудаление или ручное).
- **Порядок разработки**: сначала БД и API (бэк), затем UI. Не тратить время на фронт до рабочего API.

## Ключевые сущности БД (минимальная схема из спецификации)

| Таблица | Назначение |
|--------|------------|
| `clubs` | Клуб: название, slug, город, адрес, логотип, контакты, admin_name, status (active/suspended/trial), trial_ends_at |
| `club_subscriptions` | Подписка клуба на платформу: plan (start/basic/pro), period, price, started_at, ends_at, payment_provider, status |
| `club_members` | Участник клуба: user_id, club_id, role (admin/manager/player), status (active/invited/removed), invited_by, joined_at |
| `club_invite_links` | Инвайт-ссылки: token, expires_at, max_uses, use_count, is_active |
| `club_membership_fees` | Настройка взносов клуба: amount, period, period_start_day, restrict_tournament_access, payment (ЮKassa/Stripe), is_active |
| `club_fee_payments` | Оплаты взносов игроков: member_id, fee_id, amount, period_label, paid_at, method (online/manual), payment_ref |
| `club_ratings` | Рейтинг игрока в клубе: member_id, points, rank, updated_at |
| `club_rating_history` | История изменений рейтинга: tournament_id, points_before/after, delta |
| `club_tournament_applications` | Заявки клубов на межклубный турнир |
| Расширение `tournaments` | `club_id` (FK, nullable), `is_open_interclub` (boolean) |
| (Раздел 10) `club_plans`, `club_member_plans`, `club_plan_tournament_access`, `club_plan_slot_usage` | Клубные тарифы для игроков и лимиты |
| (Admin) `platform_audit_log` | Лог действий platform_admin |

## Рекомендуемый порядок разработки (из спецификации, §8)

1. **Этап 1 — База данных**: таблицы clubs, club_subscriptions, club_members → club_invite_links → поля club_id, is_open_interclub в tournaments → club_membership_fees, club_fee_payments → club_ratings, club_rating_history → club_tournament_applications (и при необходимости club_plans и связанные).
2. **Этап 2 — Регистрация и базовые CRUD**: шаги 1–3 регистрации клуба (сначала trial без оплаты), API клуба, публичная страница, инвайт-ссылки, добавление игрока по email.
3. **Этап 3 — ЛК игрока**: клубный контекст в шапке, переключатель клубов, «Мои турниры», рейтинг клуба, входящие приглашения.
4. **Этап 4 — Панель администратора**: дашборд, игроки, турниры (создание с club_id), рейтинги, менеджеры, настройки.
5. **Этап 5 — Финансы**: подключение ЮKassa/Stripe клуба, настройка взносов, оплата взноса игроком, webhook, мониторинг, ручная отметка.
6. **Этап 6 — Уведомления**: шаблоны писем, Telegram, CRON (напоминания, просрочки, подписка клуба).
7. **Этап 7 — Межклубные заявки и админ платформы**: UI заявок, раздел «Клубы» в админке, тарифы платформы, финансовая сводка, глобальные настройки, audit log.
8. **Этап 8 (опционально) — Клубные тарифы для игроков**: club_plans, выбор тарифа при вступлении, лимиты и слоты, «Мой тариф» в ЛК.
