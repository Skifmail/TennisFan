# Архитектура проекта TennisFan (Tennison)

## Общий подход

- **Монорепозиторий Django**: один проект `config`, приложения в `apps/`.
- **Классическая MVC Django**: модели (M), представления/формы (V/C), шаблоны в `templates/`.
- Конфигурация через **переменные окружения** и `config/settings.py`; опциональные фичи (PostgreSQL, S3, Redis) включаются флагами в env.

## Слои и границы

- **Транспорт**: `config/urls.py` → `apps.*.urls` → views (FBV/CBV).
- **Бизнес-логика**: в основном во view и формах; часть сложной логики турниров вынесена в `apps/tournaments/tvd.py` (TVD = турнирная логика, сетки, матчи).
- **Данные**: модели в `apps/*/models.py`, миграции в `apps/*/migrations/`.
- **Внешние интеграции**: Telegram (core, telegram_bot), ЮKassa (payments), Яндекс (courts geocoder), email, S3.

Зависимости направлены от API/views к моделям и сервисам; обратных зависимостей из domain-моделей к HTTP/Telegram нет.

## Ключевые домены

| Домен | Назначение |
|-------|------------|
| **users** | User (email как username), Player-профиль, уведомления, NTRP-тесты |
| **tournaments** | Турниры, матчи, сетки (олимпийская, круговая, плей-офф), заявки, рейтинги сезона |
| **courts** | Площадки (Court), заявки на добавление, фото, рейтинги, геокодер |
| **sparring** | Заявки на спарринг, ответы, парные матчи, команды |
| **training** | Тренеры, записи на тренировки |
| **content** | Новости, страницы, видео, стрингеры, галереи, контакты, правила |
| **subscriptions** | Тарифы подписок, привязка к пользователям, региональные цены |
| **payments** | Сохранённые способы оплаты, записи платежей (ЮKassa) |
| **shop** | Товары, заявки на покупку |
| **core** | Обратная связь, поддержка, Telegram-ссылки, города, футер, sitemap |
| **navigation** | Пункты меню |
| **legal** | Юр. страницы, принятие соглашений |
| **comments** | Комментарии (универсальная модель) |
| **player_ratings** | Рейтинги навыков игроков, метрики, агрегаты |
| **telegram_bot** | Вебхуки и логика бота для Telegram |

## Паттерны

- **Аутентификация**: Django auth, `User` с email; защита админки через `axes` и опционально кастомный `ADMIN_URL`.
- **Медиа**: миксин сжатия изображений (`CompressImageFieldsMixin`), валидатор размера; хранение в FS или S3.
- **Планировщик**: `django_crontab` — генерация сеток, напоминания, рекуррентные платежи, сброс очков сезона, публикация рейтингов и т.д.
- **Логирование**: стандартный Django LOGGING + упоминание loguru в requirements; логи в `logs/`.

## Точки входа

- **Web**: `config.wsgi.application` → `config.urls` → приложения по префиксам (`/`, `/users/`, `/tournaments/`, `/payments/`, и т.д.).
- **Cron**: команды management (`generate_brackets_past_deadlines`, `fan_process_overdue_matches`, `run_recurring_subscription_payments` и др.) — см. `CRONJOBS` в settings.
- **Telegram**: вебхуки в `core` (support) и в `telegram_bot`.

## Риски и зависимости

- Крупный модуль `apps/tournaments/tvd.py` (~2200+ строк) — основная турнирная логика; изменения требуют осторожности.
- Ряд приложений в mypy исключён (`import-untyped` и т.п.) — типизация не везде строгая.
- Внешние API (ЮKassa, Telegram, Яндекс) — при падении или смене API нужна адаптация в соответствующих app.
