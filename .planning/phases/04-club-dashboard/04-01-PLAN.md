# Plan 04-01: Phase 4 — Панель управления клубом (admin/manager)

**Phase:** 4 (Панель управления клубом)  
**Цель:** Дашборд клуба со статистикой и быстрыми действиями, управление игроками (список, поиск, исключение), турниры (создание с привязкой к клубу, доступ к управлению), рейтинги (таблица, экспорт), взносы (базовый UI настройки и мониторинга), приглашения (список ссылок, деактивация), менеджеры (назначение ролей), настройки клуба, отображение подписки.

**Источники:** PROJECT.md §4, ROADMAP Phase 4, club_dev_spec.docx.  
**Зависимости:** Phase 1–3 выполнены (модели, регистрация, инвайты, ЛК игрока).

---

## Prerequisites

- Доступ к дашборду: только пользователи с ролью **admin** или **manager** клуба (`user_can_manage_club`). Разграничение: **admin** — полный доступ; **manager** — без раздела «Финансы/взносы» (настройка ClubMembershipFee, мониторинг оплат), без «Настройки клуба» (редактирование профиля, is_public), без «Подписка», без «Менеджеры». Реализовать хелперы: `user_can_edit_club_settings(user, club)` → только admin; `user_can_manage_fees(user, club)` → только admin; `user_can_manage_managers(user, club)` → только admin.
- Турниры: создание через форму в панели клуба (минимальный набор полей), сохранение с `club=current_club`. Управление существующим турниром (сетки, результаты) — существующие view в `tournaments` (tournament_manage и др.); для клубных турниров разрешить доступ не только staff, но и club admin/manager (проверка: `tournament.club_id` и пользователь — admin/manager этого клуба).
- Оплата подписки и взносов (webhook, кнопка «Оплатить») — Phase 5; в Phase 4 только отображение данных и настройка параметров взноса (форма ClubMembershipFee).

## Task 1: Права доступа admin vs manager

- В `apps/clubs/services.py` добавить:
  - `user_can_edit_club_settings(user, club)` → `user_can_manage_club(user, club) and club.members.filter(user=user, role=ClubMemberRole.ADMIN, status=ClubMemberStatus.ACTIVE).exists()`
  - `user_can_manage_fees(user, club)` → то же (только admin)
  - `user_can_manage_managers(user, club)` → то же (только admin)
- Во всех view панели клуба: разделы «Настройки», «Взносы» (настройка и мониторинг), «Подписка», «Менеджеры» проверять соответствующим хелпером и при отсутствии прав возвращать 403 или редирект с сообщением.

**Проверка:** Менеджер видит дашборд, игроков, турниры, рейтинги, приглашения; не видит (или получает 403) настройки клуба, настройку взносов, подписку, назначение менеджеров.

## Task 3: Управление игроками

- **URL:** `club/<slug>/members/` (список), опционально `club/<slug>/members/export/` (CSV).
- **View список:** `ClubMember.objects.filter(club=club).select_related('user').order_by('-joined_at')` с фильтрами по статусу (active / invited / removed) и поиску по email/имени (Q по user__email, user__first_name, user__last_name). Пагинация (например по 20). В контексте передать флаг `can_edit_settings` для отображения ссылки «Исключить» (или исключение доступно и менеджеру).
- **Исключение участника:** view `club/<slug>/members/<int:member_id>/remove/` (POST). Проверка: текущий пользователь — admin или manager; исключаемый — не admin (нельзя исключить другого админа, или только один admin остаётся — не исключать последнего admin). Действие: установить `ClubMember.status=REMOVED` (и при необходимости `ClubMember.updated_at`). Редирект обратно в список с сообщением.
- **Шаблон:** `templates/clubs/members_list.html` — таблица: email, ФИО, роль, статус, дата вступления, действия (ссылка на профиль игрока на платформе — `reverse('profile', args=[member.user.player.pk])` если есть player, иначе просто email; кнопка «Исключить» для active, только не для себя и не для другого admin).
- **Экспорт CSV:** view GET `club/<slug>/members/export/`. Выдача CSV (email, first_name, last_name, role, status, joined_at). Content-Type: text/csv; filename=members_<slug>.csv.

**Проверка:** В списке отображаются участники; фильтр и поиск работают; исключение переводит в removed; экспорт отдаёт CSV.

## Task 4: Турниры клуба — список и создание

- **Список турниров:** URL `club/<slug>/tournaments/`. View: `Tournament.objects.filter(club=club).order_by('-start_date')`. Шаблон: таблица (название, дата, статус, кол-во участников); для каждого — ссылка «Управление» на `tournament_manage` (tournaments app). Доступ к `tournament_manage` для клубных турниров: в `apps/tournaments/views.py` в view `tournament_manage` (и при необходимости в `_tournament_manage_get_tournament`) добавить проверку: если у пользователя не staff, проверить, что `tournament.club_id` не пусто и что пользователь — admin или manager этого клуба (`user_can_manage_club(request.user, tournament.club)`); иначе 403.
- **Создание турнира:** URL `club/<slug>/tournaments/create/`. View GET/POST. Форма с полями: название, slug (или автогенерация из названия), city (по умолчанию — клуб.city), start_date, end_date (optional), registration_deadline (optional), format (одноэтапная/олимпийская/круговой и т.д. — из Tournament), variant (singles/doubles), gender, min_participants, max_participants. В POST: валидация, проверка лимитов по тарифу (константы: например START=1 турнир в месяц, BASIC=5, PRO=без лимита — проверять количество турниров клуба с start_date в текущем месяце). Создание `Tournament` с `club=club`, редирект на `tournament_manage` для созданного турнира. Использовать существующую модель Tournament; минимально обязательные поля заполнить, остальные — default или blank.
- **Шаблон создания:** `templates/clubs/tournament_create.html` (или форма в модальном окне — по желанию). После создания редирект на `reverse('tournament_manage', args=[new_tournament.slug])`.

**Проверка:** В панели клуба отображается список турниров клуба; ссылка «Управление» открывает страницу управления турниром для admin/manager клуба; создание нового турнира создаёт запись с club=club и ведёт на управление.

## Task 5: Рейтинг клуба в панели

- **URL:** `club/<slug>/rating/` (для админа/менеджера — полная таблица рейтинга клуба).
- **View:** те же данные, что и для раздела «Рейтинг» в ЛК игрока (Phase 3), но для всех участников: `ClubRating.objects.filter(club=club).select_related('member', 'member__user').order_by('-points')`. Вычисление места при отображении (display_rank). Передать в контекст клуб и список рейтингов.
- **Шаблон:** `templates/clubs/dashboard_rating.html` — таблица: место, участник (email/имя), очки. Кнопка «Экспорт»: CSV или Excel. Экспорт CSV: GET `club/<slug>/rating/export/` — выдача CSV (place, email, name, points). PDF в Phase 4 можно опустить или заглушить ссылкой «Скоро».

**Проверка:** Админ/менеджер видит полную таблицу рейтинга; экспорт CSV работает.

## Task 6: Взносы — настройка и мониторинг (базовый UI)

- **Доступ:** только admin (`user_can_manage_fees`).
- **Настройка взноса:** URL `club/<slug>/fees/settings/`. View GET/POST. Форма для создания/редактирования одной активной настройки `ClubMembershipFee`: amount, currency, period (monthly/quarterly/yearly), period_start_day, description, restrict_tournament_access, is_active. Провайдер оплаты (payment_provider, shop_id, api_key) в Phase 4 можно показывать как read-only или заглушку «Подключить в Phase 5». При сохранении: если записей нет — создать; если есть — обновить последнюю или создать новую (по бизнес-логике: одна активная настройка на клуб — обновлять существующую с is_active=True).
- **Мониторинг оплат:** URL `club/<slug>/fees/payments/`. View: список `ClubFeePayment.objects.filter(club=club).select_related('member', 'member__user', 'fee').order_by('-paid_at')` с фильтром по периоду (period_label). Шаблон: таблица (участник, период, сумма, дата, способ). Без возможности инициировать платёж или webhook — только просмотр и при необходимости ручная отметка «оплачено» (добавить форму: создать ClubFeePayment с method=manual, указать member, period_label, amount — только admin). Ручная отметка: форма на странице или отдельный URL POST `club/<slug>/fees/payments/mark-paid/` с полями member_id, period_label, amount.

**Проверка:** Админ видит настройку взноса и может изменить параметры; видит список оплат; может добавить ручную отметку об оплате.

## Task 7: Приглашения — список ссылок, деактивация, копирование

- **Список инвайт-ссылок:** URL `club/<slug>/invites/` (или оставить текущий `invite/create/` и добавить список на той же странице). View: `ClubInviteLink.objects.filter(club=club).select_related('created_by').order_by('-created_at')`. Шаблон: таблица (токен обрезанный, создал, срок действия, max_uses, use_count, активна, действия). Действия: «Копировать ссылку» (полный URL с token), «Деактивировать» (POST: установить is_active=False).
- **Деактивация:** POST `club/<slug>/invites/<int:pk>/deactivate/` — проверка прав, link.is_active=False, save(), редирект обратно в список.
- **Копирование ссылки:** на фронте через JavaScript (clipboard) по кнопке; полный URL: `request.build_absolute_uri(reverse('clubs:join', kwargs={'slug': club.slug}) + '?token=' + link.token)`.
- QR-код в Phase 4 можно опустить или вынести в отдельную задачу (опционально: генерация QR на стороне клиента или простой GET с URL для внешнего сервиса).

**Проверка:** В панели отображается список инвайт-ссылок; можно скопировать ссылку и деактивировать.

## Task 8: Менеджеры — назначение роли

- **Доступ:** только admin (`user_can_manage_managers`).
- **URL:** `club/<slug>/managers/`. View: список участников с ролью admin или manager (или все active с отображением роли). Форма смены роли: для каждого участника с ролью player можно назначить роль manager; для manager — вернуть в player. Админа не понижать через эту форму (или только если админов несколько — понизить одного до manager). Один участник — одна роль; при назначении manager создать/обновить запись ClubMember с role=MANAGER.
- **Шаблон:** таблица участников (email, текущая роль), для player — кнопка «Сделать менеджером», для manager — «Убрать права менеджера» (перевести в player). POST на те же URL с member_id и action=set_manager / remove_manager.

**Проверка:** Админ может назначить участника менеджером и снять права; менеджер не видит раздел или получает 403.

## Task 12: Доступ к tournament_manage для клуба

- В `apps/tournaments/views.py` в функции `tournament_manage` (и во все вспомогательные, которые проверяют доступ: `_tournament_manage_get_tournament` и др.): кроме `@staff_member_required` разрешить доступ, если `request.user.is_authenticated` и `tournament.club_id` не None и `user_can_manage_club(request.user, tournament.club)`. Вариант: заменить декоратор на кастомный `@user_passes_test` или внутри view после get_object_or_404 проверить: если не request.user.is_staff, то требовать tournament.club и user_can_manage_club(request.user, tournament.club); иначе 403. То же для view, которые вызывают `_tournament_manage_get_tournament` — эта функция должна возвращать турнир только если доступ разрешён (для staff или для club admin/manager своего клуба).

**Проверка:** Админ/менеджер клуба может открыть страницу управления турниром своего клуба без прав staff.
