# Plan 06-01: Phase 6 — Уведомления

**Phase:** 6 (Уведомления)  
**Цель:** Email- и Telegram-уведомления по ключевым событиям клубного модуля, регулярные CRON-напоминания, настройки уведомлений в ЛК игрока и панели клуба.

**Источники:** PROJECT.md §6, ROADMAP Phase 6, STATE.md (Deferred Issues по уведомлениям).  
**Зависимости:** Phase 1–5 выполнены (модели, ЛК игрока, панель клуба, финансы и CRON-команды-заглушки для напоминаний).

---

## Prerequisites

- **Почтовая инфраструктура:** использовать существующую email-интеграцию платформы (если есть) либо стандартный Django `send_mail`/`EmailMultiAlternatives` через настройки `EMAIL_BACKEND`. Шаблоны писем выносить в `templates/emails/clubs/…`.
- **Telegram-инфраструктура:** планируется интеграция с Telegram-ботом платформы (один бот для всей платформы). Отправка сообщений инкапсулируется в сервисе `apps.clubs.services` или отдельном модуле `apps.clubs.notifications`, который использует инфраструктурный клиент Telegram (например, `infrastructure/telegram_client.py` или существующий модуль в проекте).
- **CRON/periodic tasks:** использовать существующий механизм планировщика (management commands + внешние cron, django-crontab, Celery-beat и т.п.). В Phase 5 уже созданы команды `send_club_fee_reminders` и `send_club_subscription_reminders` — здесь они дополняются реальной отправкой уведомлений.
- **Настройки уведомлений:** хранить настройки (email/Telegram) на двух уровнях:
  - Игрок (user/member) — предпочитаемые каналы и типы уведомлений.
  - Клуб (club) — глобальные настройки уведомлений для клуба (включены/выключены, какие события отправлять).

---

## Task 1: Модель и настройки уведомлений

- Добавить модели/поля для хранения настроек уведомлений:
  - Для игрока: либо новые поля в существующей модели пользователя/профиля (например, `UserProfile`), либо отдельная модель `ClubNotificationSettings` (FK на пользователя и, при необходимости, на клуб). Минимум: флаги `email_enabled`, `telegram_enabled`, отдельные флаги по типам событий можно добавить позже.
  - Для клуба: в модели `Club` или отдельной модели `ClubNotificationConfig` сохранить флаги `notify_by_email`, `notify_by_telegram` и отдельные флаги по событиям (например, `notify_fee_reminders`, `notify_tournament_reminders`, `notify_subscription_expiring`).
- Добавить миграции для новых моделей/полей.
- Обновить `STATE.md`, если будут приняты решения по структуре (общая модель настроек или раздельные).

**Проверка:** настройки уведомлений сохраняются в БД, значения корректно читаются при формировании уведомлений.

---

## Task 2: Email-шаблоны для клубных событий

- Создать папку шаблонов писем для клубных уведомлений: `templates/emails/clubs/`.
- Добавить HTML/текстовые шаблоны (минимальные, но рабочие) для следующих событий:
  - Приглашение в клуб (по email) — ссылка на подтверждение вступления.
  - Напоминание о членском взносе (7 и 3 дня до окончания периода).
  - Уведомление о просрочке членского взноса.
  - Уведомление «взнос оплачен» игроку.
  - Напоминание о турнире (24 часа и 1 час до начала).
  - Уведомление о результатах турнира (опционально — ссылка на результаты).
  - Уведомление админу клуба о новом игроке.
  - Сводка должников по клубу (периодическая).
  - Напоминания об истечении подписки клуба (7 и 3 дня).
- Для каждого шаблона предусмотреть базовый контекст: название клуба, имя игрока (если применимо), ссылки на ЛК, даты, суммы, статусы.

**Проверка:** рендеринг каждого шаблона через shell/management command или тест показывает валидный HTML/текст без ошибок.

## Task 3: Сервис уведомлений (email + Telegram)

- Создать модуль сервиса уведомлений в `apps/clubs` (например, `apps/clubs/services.py` или `apps/clubs/notifications.py`, если его ещё нет/нужно расширить):
  - Функции высокого уровня вида:
    - `send_club_invite_email(...)`
    - `send_fee_reminder_notifications(...)`
    - `send_fee_overdue_notifications(...)`
    - `send_fee_paid_notifications(...)`
    - `send_tournament_reminder_notifications(...)`
    - `send_subscription_expiring_notifications(...)`
    - `send_club_debtors_summary(...)`
  - Внутри использовать:
    - Email-отправку на базе Django (общий helper для отправки писем с логированием успеха/ошибок).
    - Telegram-отправку через абстракцию `TelegramClient` (если уже есть в проекте; иначе — предусмотреть точку расширения и оставить заглушки, логирующие намерение отправить в Telegram).
- Все функции сервиса должны:
  - Учитывать настройки получателя (email/Telegram включены или нет).
  - Не логировать чувствительные данные.
  - Логировать ключевые события (успех/ошибка отправки) через `loguru`.

**Проверка:** вызов сервисных функций из Django shell/тестов приводит к отправке писем (и/или логированию попытки отправки в Telegram); ошибки корректно логируются.

## Task 4: Интеграция уведомлений в существующие флоу

- Встроить сервис уведомлений в уже реализованные бизнес-процессы:
  - При создании приглашения в клуб по email — отправка письма «Приглашение в клуб».
  - При успешной оплате членского взноса (return или webhook из Phase 5) — отправка уведомления игроку «Взнос оплачен» и, опционально, админу клуба.
  - При успешной оплате подписки клуба платформе — уведомление админу клуба.
  - При добавлении нового игрока в клуб (через инвайт или ручное добавление) — уведомление админу клуба.
  - При создании/изменении турнира клуба — опциональная отправка напоминаний (см. Task 5 для CRON).
- При интеграции:
  - Не допускать дублирования уведомлений (особенно при двойной обработке return + webhook).
  - Обернуть вызовы сервиса уведомлений в try/except с логированием ошибок, чтобы сбой уведомлений не ломал основной бизнес-флоу.

**Проверка:** ключевые действия в системе (оплата, приглашение, вступление, создание турнира) инициируют корректные вызовы сервиса уведомлений.

## Task 5: CRON‑напоминания и периодические уведомления

- Расширить существующие management-команды `send_club_fee_reminders` и `send_club_subscription_reminders`:
  - Добавить выборку игроков/клубов по условиям:
    - Взносы: напоминания за 7 и 3 дня до конца периода; уведомления о просрочке.
    - Подписка клуба: напоминания за 7 и 3 дня до окончания; при переходе в suspended.
  - Для каждого получателя вызывать соответствующие функции сервиса уведомлений.
- Реализовать дополнительные команды (или расширить существующие), если необходимо:
  - Сводка должников по клубу (еженедельная/ежедневная рассылка админу).
  - Напоминания о турнире (24 часа и 1 час до начала) по записавшимся игрокам.
- Обеспечить идемпотентность:
  - Внутри команд хранить отметку о том, что конкретное напоминание уже отправлено (например, в вспомогательных моделях или через поля «last_reminder_sent_at»/«last_status_notified_at»), либо использовать расчётные критерии, исключающие повторную отправку в тот же день/период.

**Проверка:** запуск команд формирует корректные запросы к сервису уведомлений и не создаёт дубликатов при повторном запуске за один и тот же период.

## Task 6: Настройки уведомлений в ЛК игрока и панели клуба

- Добавить UI для управления настройками уведомлений:
  - В ЛК игрока — раздел «Уведомления», где пользователь может включать/выключать email и Telegram, а также (опционально) отдельные типы уведомлений.
  - В панели клуба — раздел/вкладка «Уведомления» в настройках клуба, где админ может включать/выключать отправку определённых типов уведомлений клубу и игрокам (в рамках разрешённой логики).
- Обновить соответствующие views и шаблоны `templates/clubs/…`:
  - Формы с валидацией и сохранением настроек в модели из Task 1.
  - Информативные описания для каждого чекбокса.
- Проверить, что новые настройки реально учитываются сервисом уведомлений (Task 3).

**Проверка:** игрок и админ клуба могут изменить настройки уведомлений, и изменения сразу влияют на отправку уведомлений.

---

## Task 7: Логирование и мониторинг уведомлений

- В сервисе уведомлений ввести единообразное структурированное логирование через `loguru`:
  - Поля: тип уведомления, канал (email/telegram), получатель (идентификатор), клуб, статус (успех/ошибка), причина ошибки.
  - Не логировать email-адреса целиком (маскировать) и другие чувствительные данные.
- (Опционально) Добавить в админку Django:
  - Просмотр логов/истории отправок (через модель `NotificationLog`, если будет введена).
  - Фильтры по клубу, пользователю, типу уведомления и дате.

**Проверка:** при отправке уведомлений в логах видно понятные, структурированные записи, пригодные для отладки и мониторинга.
