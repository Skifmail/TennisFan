# Plan 07-01: Phase 7 — Межклубные заявки и админ платформы

**Phase:** 7 (Межклубные заявки и админ платформы)  
**Цель:** UI межклубных турниров (заявки клубов), полноценный раздел «Клубы» для владельца платформы (Django Admin), управление тарифами и глобальные настройки, аудит-лог действий platform_admin.

**Источники:** PROJECT.md §7–8, ROADMAP Phase 7, STATE.md.  
**Зависимости:** Phase 1–6 выполнены. Модель `ClubTournamentApplication` и поле `is_open_interclub` в `Tournament` уже созданы (Phase 1). Django Admin для клубных моделей зарегистрирован минимально (`apps/clubs/admin.py`).

---

## Prerequisites

- **Межклубные турниры:** модель `ClubTournamentApplication` (Phase 1) и поле `Tournament.is_open_interclub` уже в БД. В Phase 4 форма создания турнира (`ClubTournamentCreateForm`) не использует `is_open_interclub`. Нужно: добавить чекбокс в форму (только для тарифа Про), view для подачи/обработки заявок, шаблоны.
- **Django Admin:** существующая регистрация в `apps/clubs/admin.py` — базовые `ModelAdmin` для всех клубных моделей. Нужно: расширить с инлайнами, действиями (блокировка, смена тарифа, ручное продление), детальной страницей клуба, финансовой сводкой.
- **Audit log:** спецификация упоминает `platform_audit_log` — таблица для записи действий platform_admin (блокировка клуба, смена тарифа, удаление и т.д.). Реализовать как Django-модель с автоматической записью из admin-действий.
- **Глобальные настройки платформы:** trial_days, хранение данных suspended, автоудаление, открытие/закрытие регистрации клубов — можно хранить в `django.contrib.sites`-подобной модели или в отдельной `PlatformSettings` (singleton).

## Task 1: UI межклубных турниров — чекбокс и ограничение по тарифу

- В форме создания турнира клуба (`ClubTournamentCreateForm` или view `tournament_create`) добавить чекбокс «Открытый межклубный» (`is_open_interclub`):
  - Показывать чекбокс только если текущая подписка клуба — тариф **Про**.
  - При POST: если чекбокс отмечен и тариф не Про — игнорировать (или показать ошибку).
  - При сохранении турнира передавать значение в `Tournament.objects.create(…, is_open_interclub=…)`.
- Обновить шаблон `tournament_create.html`: условный блок с чекбоксом.

**Проверка:** Клуб на тарифе Про видит чекбокс; клуб на Старт/Базовый — не видит. Турнир с `is_open_interclub=True` сохраняется в БД.

## Task 2: Подача заявки клубом на межклубный турнир

- На публичной странице турнира (`tournament_detail`) или на странице клубного турнира — если `tournament.is_open_interclub` и пользователь является админом другого клуба (не организатора):
  - Показать кнопку «Подать заявку от клуба».
  - По нажатию: view `POST club_tournament_apply` — создать `ClubTournamentApplication(tournament=…, applicant_club=…, status=pending, message=…)`.
  - Проверка дубликатов: unique_together уже стоит на (tournament, applicant_club).
  - Если заявка уже подана — показать статус вместо кнопки.
- URL: `club/<slug:slug>/tournaments/<int:tournament_id>/apply/` (POST).
- Шаблон: небольшая форма с полем «Комментарий» (опционально) и кнопкой.

**Проверка:** Админ клуба-заявителя видит кнопку, подаёт заявку; повторная подача невозможна; статус отображается.

## Task 3: Раздел «Межклубные заявки» в панели организатора

- В панели клуба-организатора (дашборд) добавить раздел «Межклубные заявки» (ссылка в навигации дашборда).
- View `club_interclub_applications(request, slug)` — список заявок на турниры этого клуба с `is_open_interclub=True`.
  - Фильтры: по турниру, по статусу (pending/approved/rejected).
  - Для каждой заявки: клуб-заявитель, дата, статус, кнопки «Одобрить» / «Отклонить».
- Views для одобрения/отклонения: `POST club_application_respond(request, slug, pk)` — обновить `status`, `responded_by`, `responded_at`.
- URL: `<slug>/interclub-applications/`, `<slug>/interclub-applications/<int:pk>/respond/`.
- Шаблон: таблица с заявками и действиями.

**Проверка:** Организатор видит входящие заявки, может одобрить/отклонить; статус обновляется.

## Task 4: Модель PlatformAuditLog и запись действий

- Создать модель `PlatformAuditLog` в `apps/clubs/models.py` (или в отдельном `apps/clubs/audit.py`, если предпочтительнее):
  - `action` — CharField (например: `club_blocked`, `club_unblocked`, `plan_changed`, `subscription_extended`, `club_deleted`, `trial_reset`).
  - `actor` — FK на `AUTH_USER_MODEL` (кто выполнил действие; platform_admin = staff/superuser).
  - `club` — FK на Club (nullable, если действие глобальное).
  - `details` — TextField (JSON или текст с деталями действия).
  - `created_at` — DateTimeField(auto_now_add=True).
- Добавить миграцию.
- Утилитная функция `log_platform_action(actor, action, club=None, details="")` для записи.

**Проверка:** При вызове `log_platform_action(…)` запись создаётся в БД и видна в Django Admin.

## Task 5: Расширение Django Admin — раздел «Клубы» для platform_admin

- Расширить `ClubAdmin` в `apps/clubs/admin.py`:
  - **Инлайны:** `ClubSubscriptionInline` (TabularInline), `ClubMemberInline` (TabularInline, readonly), `ClubMembershipFeeInline`.
  - **Действия (actions):**
    - `block_clubs` — перевести выбранные клубы в status=suspended + запись в audit log.
    - `unblock_clubs` — перевести в status=active + audit log.
    - `delete_clubs_with_data` — мягкое удаление (status=suspended + пометка, или hard delete с подтверждением) + audit log.
  - **Кнопки/Ссылки на change_form:**
    - «Продлить подписку вручную» — custom view или action для создания/продления `ClubSubscription`.
    - «Сменить тариф» — action для обновления плана текущей активной подписки + audit log.
    - «Сбросить trial» — обновить `trial_ends_at` + audit log.
  - **Фильтры:** по статусу, тарифу текущей подписки (ListFilter с подзапросом), городу, дате регистрации.
  - **Readonly fields:** `created_at`, количество участников (аннотация), количество турниров.
- Зарегистрировать `PlatformAuditLog` в admin:
  - `list_display`: actor, action, club, created_at.
  - `list_filter`: action, created_at.
  - `search_fields`: club__name, actor__email.
  - `readonly_fields`: все (лог только для чтения).

**Проверка:** В Django Admin раздел «Клубы» позволяет блокировать, менять тариф, продлять подписку, видеть инлайны; все действия записываются в audit log.

## Task 6: Финансовая сводка по подпискам платформы

- Создать custom admin view (или использовать `django-admin-tools` / простой view с template) для финансовой сводки:
  - URL: `admin/clubs/financial-summary/` (custom view в `ClubAdmin` через `get_urls()`).
  - Данные:
    - Общее количество активных подписок по тарифам (Старт/Базовый/Про).
    - Суммарный MRR (Monthly Recurring Revenue) по активным подпискам.
    - Количество клубов с истекающими подписками (в ближайшие 7/30 дней).
    - Количество suspended клубов.
    - Общая выручка за текущий месяц (сумма `ClubSubscription.price` для подписок, созданных в этом месяце).
  - Шаблон: `templates/admin/clubs/financial_summary.html` — таблица/карточки с цифрами.

**Проверка:** Ссылка «Финансовая сводка» в списке клубов ведёт на страницу с актуальными данными.

## Task 7: Глобальные настройки платформы (PlatformSettings)

- Создать модель `PlatformSettings` (singleton, одна запись):
  - `trial_days` — PositiveIntegerField (сколько дней trial, по умолчанию 14).
  - `suspended_data_retention_days` — PositiveIntegerField (сколько дней хранить данные suspended клуба перед удалением, по умолчанию 30).
  - `auto_delete_suspended` — BooleanField (автоудаление suspended клубов по истечении retention, default=False).
  - `registration_open` — BooleanField (открыта ли регистрация новых клубов, default=True).
- Миграция.
- Зарегистрировать в Django Admin (singleton — в `get_queryset` показывать только одну запись; кнопка «Add» скрыта если запись уже есть).
- При регистрации клуба (`create_club_with_trial`) использовать `PlatformSettings.trial_days` вместо захардкоженных 14 дней.
- Создать management-команду `cleanup_suspended_clubs` (или расширить существующую), которая удаляет suspended клубы с истёкшим retention + audit log. Зарегистрировать в CRONJOBS.

**Проверка:** В Django Admin можно изменить trial_days; регистрация клуба использует новое значение; suspended клубы удаляются CRON-командой.

## Task 8: CRON-команда перевода в suspended при истечении подписки

- Создать (или расширить `send_club_subscription_reminders`) management-команду `suspend_expired_clubs`:
  - Выбрать клубы, у которых **нет активных подписок** (все `ClubSubscription` с `status != active` или `ends_at < now`).
  - Клубы со статусом `active` или `trial` (и `trial_ends_at < now`) → перевести в `suspended`.
  - Записать в audit log (`action=club_auto_suspended`).
  - Отправить уведомление админам клуба через `send_subscription_expiring_notifications` (или отдельное уведомление «Подписка приостановлена»).
- Зарегистрировать в CRONJOBS (ежедневно, напр. в 02:00).

**Проверка:** Клуб с истёкшей подпиской автоматически переводится в suspended; audit log содержит запись.
