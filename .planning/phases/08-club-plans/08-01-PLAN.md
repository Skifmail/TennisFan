# Plan 08-01: Phase 8 — Клубные тарифы для игроков (опционально)

**Phase:** 8 (Клубные тарифы для игроков, опционально)  
**Цель:** Добавить в клубный модуль настраиваемые тарифы игроков (например, Юниор/Взрослый/VIP), лимиты на турниры и слоты, выбор тарифа при вступлении, отображение текущего тарифа и учёт остатков в ЛК игрока.

**Источники:** PROJECT.md §9, ROADMAP Phase 8, STATE.md.  
**Зависимости:** Phase 1–7 выполнены (клубы, подписки, взносы, ЛК игрока, панель клуба, межклубные заявки, админ платформы).

---

## Prerequisites

- **Сущности Phase 8:** согласно ROADMAP нужны таблицы `club_plans`, `club_member_plans`, `club_plan_tournament_access`, `club_plan_slot_usage`.
- **Текущий контекст membership:** в проекте уже есть модели клуба и участников (`Club`, `ClubMember`) и флоу вступления (invite/join). Нужно встроить выбор тарифа без поломки текущего вступления.
- **Турнирный контекст:** в клубных турнирах уже есть запись игроков; нужно добавить проверку доступа по тарифу и списание лимитов/слотов при записи.
- **Совместимость:** функционал опциональный, поэтому при отсутствии тарифов у клуба система должна продолжать работать по текущей логике (fallback).

---

## Task 1: Модели тарифов игроков и миграции

- Добавить/обновить модели в `apps/clubs/models.py`:
  - `ClubPlan` (`club`, `name`, `description`, `is_active`, `monthly_fee`, `max_tournaments_per_month`, `monthly_slots`, `allow_rollover_slots`, `rollover_cap`, `sort_order`, timestamps).
  - `ClubMemberPlan` (`club_member`, `plan`, `status`, `started_at`, `ended_at`, `auto_renew`, `assigned_by`, `change_reason`).
  - `ClubPlanTournamentAccess` (`plan`, `tournament`, `is_allowed`) — явная привязка доступности турнира к тарифам.
  - `ClubPlanSlotUsage` (`club_member`, `plan`, `period_year`, `period_month`, `slots_used`, `rollover_in`, `rollover_out`, `tournaments_used`).
- Добавить ограничения/индексы:
  - уникальность тарифа в рамках клуба по `(club, name)` (с учётом активных/архивных по необходимости),
  - уникальность использования по периоду `(club_member, period_year, period_month)`,
  - check constraints на неотрицательные лимиты.
- Подготовить миграцию `apps/clubs/migrations/0005_...` (номер уточняется автоматически текущей веткой миграций).

**Проверка:** миграции применяются без ошибок; модели видны в Django shell/admin; базовые ограничения срабатывают.

---

## Task 2: Сервисная логика тарифов и расчёта лимитов

- Создать сервисный модуль (например, `apps/clubs/services/plans.py` или расширить `apps/clubs/services.py`) с use-case функциями:
  - создание/редактирование/архивация тарифа клуба,
  - назначение тарифа участнику,
  - смена тарифа участника (с политикой: сразу или с нового периода),
  - расчёт доступных турниров/слотов на текущий период,
  - списание лимита при регистрации на турнир и откат при отмене.
- Ввести единый helper расчёта периода (год/месяц), чтобы одинаково использовать в UI, валидации и CRON.
- Учесть fallback:
  - если у клуба нет тарифов, участник может записываться по прежней логике;
  - если тарифы включены, но участнику не назначен тариф, показывать явное сообщение и блокировать запись (или автоприсвоение default-тарифа — решение фиксируется в Notes/STATE).

**Проверка:** сервисные функции покрывают основные сценарии и возвращают предсказуемые статусы/ошибки для views.

---

## Task 3: Панель клуба — управление тарифами

- Добавить раздел `/club/<slug>/dashboard/plans/`:
  - список тарифов клуба (активные/архивные),
  - форма создания/редактирования (название, взнос, лимиты, слоты, несгораемые слоты),
  - действия активации/деактивации/архивации.
- Добавить UI управления доступом турниров по тарифам:
  - на странице турнира или отдельной странице — отметить, какие тарифы имеют доступ.
- Добавить валидацию:
  - лимиты и слоты не могут быть отрицательными,
  - rollover_cap обязателен/валиден только при `allow_rollover_slots=True`.

**Проверка:** админ/менеджер клуба может полностью управлять тарифами и настройками доступа турниров из панели клуба.

---

## Task 4: Вступление и смена тарифа участником

- На этапе вступления по инвайту/регистрации в клуб:
  - если у клуба есть активные тарифы — показать выбор тарифа,
  - сохранить выбор в `ClubMemberPlan` при подтверждении вступления.
- В ЛК игрока добавить сценарий смены тарифа (если клуб разрешает):
  - список доступных тарифов,
  - подтверждение смены,
  - отображение даты вступления в силу.
- Защитить операции правами:
  - участник может менять только свой тариф,
  - админ/менеджер клуба может назначать тарифы участникам клуба.

**Проверка:** новый участник выбирает тариф при вступлении; существующий участник может сменить тариф по правилам клуба.

---

## Task 5: Блок «Мой тариф» в ЛК игрока

- Добавить в клубный ЛК игрока блок «Мой тариф»:
  - название тарифа и бейдж,
  - размер взноса (если применимо),
  - лимит турниров/слотов на месяц,
  - остаток лимитов и слотов на текущий период,
  - подсказка по политике несгораемых слотов.
- Добавить информативные состояния:
  - тариф не назначен,
  - тариф не активен,
  - лимит исчерпан.

**Проверка:** игрок в клубном контексте видит актуальную информацию по своему тарифу и остаткам.

---

## Task 6: Ограничения записи на турниры по тарифам

- Встроить проверки в флоу записи участника на турнир:
  - доступность турнира для текущего тарифа (`ClubPlanTournamentAccess`),
  - остаток лимита турниров и слотов,
  - атомарное списание использования при успешной записи.
- Добавить откат использования:
  - при отмене записи,
  - при удалении/отмене турнира (если логика позволяет).
- Обеспечить защиту от гонок:
  - использовать транзакции/`select_for_update` для записи usage в конкурентных сценариях.

**Проверка:** запись блокируется при отсутствии доступа/лимита; usage корректно списывается и восстанавливается.

---

## Task 7: CRON переноса несгораемых слотов

- Создать management-команду, например `rollover_club_plan_slots`:
  - запускается 1-го числа месяца (или ежедневно с проверкой периода),
  - рассчитывает остатки слотов прошлого периода,
  - переносит остатки по правилам тарифа (`allow_rollover_slots`, `rollover_cap`),
  - пишет итог в `ClubPlanSlotUsage.rollover_in/rollover_out`.
- Добавить регистрацию в `CRONJOBS` (или текущем механизме расписания проекта) и запись в документацию (`crontab.example` при необходимости).

**Проверка:** после выполнения команды остатки корректно переносятся и учитываются в следующем периоде.

## Task 8: Админка, тесты и обратная совместимость

- Django Admin:
  - зарегистрировать новые модели (`ClubPlan`, `ClubMemberPlan`, `ClubPlanTournamentAccess`, `ClubPlanSlotUsage`),
  - добавить фильтры и поиск по клубу/участнику/статусу.
- Тесты:
  - unit-тесты сервисной логики расчёта лимитов и rollover,
  - интеграционные тесты выбора тарифа при вступлении и записи на турнир,
  - тесты edge-cases: отсутствие тарифа, исчерпание лимита, конкурентные записи.
- Обратная совместимость:
  - убедиться, что клубы без настроенных тарифов продолжают работать по прежнему сценарию.

**Проверка:** тестовый набор проходит; существующие пользовательские флоу не ломаются.
