# CSS MAP: `static/css/style.css`

Документ фиксирует структуру текущего CSS-файла для последующего рефакторинга.
Анализ выполнен без изменений в `static/css/style.css`.

---

## 1) Базовые стили: примерный объём

Общий размер файла: **~11 780 строк**.

- **Variables (`:root`)**: примерно **~75 строк**  
  Основной блок: `47-116` (цвета, типографика, spacing, radius, transitions, shadows, hero-переменные).  
  Дополнительный блок переменных: `688-692` (loading-система).
- **Typography**: примерно **~130-170 строк**  
  Включая `@font-face` (`7-45`), блок заголовков/навигации (`118-137`) и часть глобальных текстовых правил в ранних базовых секциях.
- **Reset / base normalize**: примерно **~105-120 строк**  
  Ключевой reset-блок: `139-245` (`*`, `html`, `body`, базовые `a`, `img`, списки, controls).

Примечание: это оценка по диапазонам и смысловым блокам, не строгий подсчёт AST.

## 4) Очевидные дубликаты / зоны риска дублирования

Найдено несколько явных сигналов дублирования и/или расползания ответственности:

- **Повторный `:root`**
  - основной `:root`: `47-116`,
  - второй `:root`: `688-692` (loading-переменные).  
  Это не ошибка само по себе, но признак разнесённых базовых переменных.

- **Повторные определения одних и тех же классов в нескольких местах**
  - `.auth-form` встречается очень часто (около `41` вхождений селектора),
  - `.btn` и производные — множественные переопределения (`~29+`),
  - `.player-card` — множественные вариации (`~28+`),
  - `.nav-dropdown*` блоки повторяются в разных местах (`~8+` на ключевые селекторы).
  Часть повторов объяснима media-query и контекстом, но объём высокий и требует консолидации.

- **Явный legacy-блок**
  - комментарий `10575`: «Старые стили для обратной совместимости (можно удалить позже)».  
  Это прямой кандидат на ревизию/удаление после проверки использования.

- **Смешение base/component/page в одном файле**
  - рядом сосуществуют reset/utility, сложные компонентные блоки и узкостраничные стили;
  - повышает риск «тихих» дубликатов при доработках.

## Краткий итог для следующего шага рефакторинга

- Потенциальная целевая декомпозиция: `base` (reset/variables/typography) -> `components` (buttons/forms/cards/nav) -> `pages` (auth/profile/shop/tournament/...).
- При рефакторинге сначала стоит инвентаризировать и объединить повторяющиеся блоки `auth`, `btn`, `card`, `nav-dropdown`.
