## Незакрытый результат аудита безопасности

Проверка повторена 19 октября 2026. Аудитор указывает одну известную уязвимость Twisted 26.4.0 и не предлагает исправленную версию; PyPI на момент проверки также публикует 26.4.0 как последнюю версию.

Уязвимость относится к обработке IMAP-шаблонов почтовым сервером Twisted. В коде и конфигурации проверяемого Tennison IMAP-сервер не обнаружен: Daphne используется для HTTP/WebSocket. При загрузке Daphne и ASGI модуль `twisted.mail.imap4` не загружается. Это свидетельства ограниченной применимости, **не удаление уязвимости из установленного пакета и не автоматическое разрешение публикации**.

Источник: [официальное предупреждение Twisted](https://github.com/twisted/twisted/security/advisories/GHSA-8pqf-f4m5-798g).

Существующий CI запускает `pip-audit` без исключений, поэтому этот результат блокирует его audit-шаг. Обновление/проверенный backport зависимости либо узкое временное исключение после оценки применимости требуют отдельного решения. В рамках этой подготовки зависимости, audit-политика и установленный пакет Twisted не изменялись.

## Перед разрешением публикации

1. Отдельно закрыть результат аудита Twisted; не отключать сканирование целиком.
2. Проверить реальную сборку контейнера и CI. Поскольку локальный runbook предупреждает о возможном Auto Deploy при push в main, сначала проверить актуальную конфигурацию доставки; не выполнять push как безобидную проверку.
3. Получить явное согласие на публикацию. Это согласие ещё не давалось.
4. После публикации проверить worker, манифест и подписку на физических Android/iPhone по [основному чек-листу](onesignal-web-push.md), отправляя только тестовым подписчикам.

## Исправление установки инструментов CI

Пользователь показал журнал старого GitHub Actions run «Правки» #13: ошибка на
`Install locked runtime and test tools`, до аудита, тестов и проверки типов.
`requirements-dev.txt` включал хешированный runtime-lock, но содержал незакреплённые
диапазоны инструментов. pip включает обязательные хеши для всего набора, поэтому
отклонил `black>=26.1,<27`. Успех Docker job не проверял этот dev-файл.

Локальное исправление:

- Диапазоны перенесены в `requirements-dev.in`, который включает прежний runtime-lock.
- `requirements-dev.txt` скомпилирован в полный список точных версий с SHA256.
- CI явно требует хеши и для dev-установки; проверки безопасности не отключены.
- Добавлены 4 регрессионные проверки: точные версии/хеши, сохранение runtime-пакетов,
  соблюдение исходных диапазонов инструментов и обязательная хеш-проверка в команде CI.
- RED подтверждён до исправления lock-файла и отдельно до исправления команды CI.
- В новом окружении Python 3.12 штатным pip выполнена реальная последовательная
  установка runtime + dev с `--require-hashes`; `pip check` завершился успешно.
- В новом pytest-django отсутствует прежний `SettingsWrapper`. Сначала воспроизведена
  ошибка импорта существующего теста, затем тест переведён на стандартный Django
  `override_settings(MEDIA_ROOT=tmp_path)`. Проверка настоящего файла и его URL сохранена.
- В новом окружении 33 целевые unit-проверки проходят. Дополнительно 73 проверки
  согласий/аватара и lock-файлов проходят с обычным хешером на PostgreSQL.
- Обе группы mypy/Black/Ruff из workflow, включая существующие модули и OneSignal,
  выполнены новыми инструментами из dev-lock и проходят. Новый тест lock-файлов также
  отдельно прошёл mypy strict с Django plugin, Black и Ruff.

  websockets 17.2. Удалены Daphne, Twisted, pyOpenSSL и более не нужная цепочка.

  `pip check` проходит; `find_spec` подтверждает отсутствие Daphne/Twisted/OpenSSL.

  Исключений, `continue-on-error` или отключения аудита не добавлено.
- Оба Compose-файла, Procfile и оба процесса CI запускают
  `--ws websockets-sansio`, ping 20 s / timeout 30 s, lifespan off и graceful
