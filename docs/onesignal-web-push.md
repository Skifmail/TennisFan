# OneSignal Web Push — подключение и проверка

Предрелизная проверка и оставшиеся ограничения: [отчёт от 19 октября 2026](onesignal-preflight-2026-10-19.md). Публикация не выполнялась; результат аудита безопасности Twisted требует отдельного решения.

## Что реализовано

- Web SDK v16 с публичным App ID `c6e46e19-f9f8-4df3-b53d-44f49da24af2`.
- Worker `/OneSignalSDKWorker.js` без авторизации, с JavaScript MIME-типом и `Cache-Control: no-cache`.
- `/manifest.webmanifest` с режимом `standalone` и существующей квадратной иконкой TennisFan.
- Блок «Уведомления на устройстве» перед футером: включение, отключение, статус подписки и инструкция для iPhone/iPad.
- Запрос разрешения только после нажатия кнопки. Автоматический welcome push отключён.
- Подключение только на одном заданном origin. На `www`, TennisTop и localhost SDK по умолчанию не загружается.

Подписки **анонимные и привязаны к браузеру, а не к аккаунту игрока**. Выход из аккаунта их не отключает. Email, телефоны и ID игроков интеграция не передаёт; сам SDK работает с техническими данными браузера и подписки. Это первый тестовый этап для общих уведомлений, не для личной переписки и событий аккаунта.

Автоматические отправки, серверные секретные ключи, привязка аккаунтов и проверка их идентичности в этот этап не входят. Существующие уведомления внутри сайта не менялись. Интеграция не кэширует страницы, не добавляет offline-режим и не отправляет рассылки сама.

## Настройка кабинета — перед публикацией

1. Открыть нужный проект → **Settings → Push & In-App → Web**.
2. Выбрать **Custom Code**: ручной запрос разрешения настроен в коде. Не оставлять **Typical Site** с автоматическими запросами из кабинета.
3. Указать Site Name `TennisFan` и Site URL `https://tennisfan.ru` — без `www` и путей.
4. Оставить стандартное расположение worker в корне: `/OneSignalSDKWorker.js`, scope `/`.
5. Проверить значок уведомления и сохранить настройки. Секретный API-ключ для Web SDK не нужен.

Если основной адрес другой, сначала согласовать его и поменять **и Site URL в OneSignal, и ONESIGNAL_SITE_ORIGIN**. Один App ID нельзя одновременно использовать для нескольких origin.

## Настройки окружения

```dotenv
ONESIGNAL_APP_ID=c6e46e19-f9f8-4df3-b53d-44f49da24af2
ONESIGNAL_SITE_ORIGIN=https://tennisfan.ru
```

Это значения по умолчанию. Для отключения SDK и новых подписок установить `ONESIGNAL_APP_ID=` и перезапустить приложение. Не удалять worker: он остаётся доступен существующим подписчикам. Отключение SDK не отзывает разрешения и не прекращает отправки из кабинета OneSignal.

Для стенда использовать отдельный OneSignal App ID и соответствующий точный HTTPS-origin с доверенным сертификатом. HTTP localhost намеренно не разрешён. Не менять Site URL production-проекта ради localhost.

## Публикация и ручная приёмка

Публикация — только после отдельного согласования. Выполнить обычную сборку/collectstatic; worker и manifest обслуживаются Django, а не staticfiles. Миграций БД нет.

После публикации:

1. Открыть `https://tennisfan.ru/OneSignalSDKWorker.js`: HTTP 200 без редиректа и входа; содержимое — `importScripts(...)`, тип `application/javascript`.
2. Открыть `/manifest.webmanifest`: HTTP 200 с `application/manifest+json`; проверить URL иконки. Проверить отсутствие ошибок SDK и регистрации worker в браузере.
3. Android/Chrome: открыть сайт не в инкогнито, нажать кнопку включения, разрешить уведомления.
4. iPhone с iOS 16.4+: открыть в Safari, «Поделиться» → «На экран Домой», запустить через иконку, включить уведомления. Обычная вкладка браузера не заменяет standalone-приложение.
5. В OneSignal найти подписку в **Audience → Users & subscriptions → Subscriptions**, проверить статус **Subscribed**, добавить каждое тестовое устройство в **Test Users**.
6. Отправить уведомление **только тестовым устройствам**. Проверить получение при закрытом сайте и открытие указанной страницы. Не отправлять всей аудитории.
7. Выключить подписку кнопкой сайта, проверить статус в кабинете. Включить обратно: повторный запрос уже выданного разрешения не нужен.
8. Проверить отказ и инструкцию по восстановлению разрешения в настройках браузера/ОС.

Push не гарантирует мгновенную доставку: влияют интернет, разрешения, настройки ОС и срок жизни сообщения. Локальные тесты не подтверждают доставку на реальные Android/iPhone и готовность production.

## Локальные проверки

```bash
venv/bin/pytest tests/unit/test_web_push.py tests/integration/test_web_push.py
WEB_PUSH_BROWSER_TESTS=1 venv/bin/pytest tests/e2e/test_web_push_browser.py
```

Для браузерных проверок требуется Chromium Playwright. Для уже установленного совместимого браузера указать `CHAT_BROWSER_EXECUTABLE`. Без `WEB_PUSH_BROWSER_TESTS=1` браузерные тесты пропускаются. В CI они запускаются отдельным шагом после установки Chromium. Тесты перехватывают сеть и подменяют SDK, не создавая реальных подписок и рассылок.
