# Одиночная связь матча с откликом на спарринг

## Причина предупреждения cron

`Match.sparring_response` был `ForeignKey(unique=True)`. Django выводил
`fields.W342` при каждой проверке моделей, в том числе при запуске нескольких
ежеминутных cron-задач. Это предупреждение о форме ORM-связи, а не ошибка
выполнения задания или перезапуск контейнера.

## Исправление

- Поле объявлено как `OneToOneField`, с прежними `null=True`, `blank=True`
  и `on_delete=SET_NULL`. Обратное обращение теперь `response.match`.
- Шаблон «Мои заявки» и предварительная загрузка используют одиночный матч.
  Отсутствующая связь не ломает карточку; существующая ссылка «Матч» сохранена.
- Административная колонка «Матч создан» учитывает оба состояния.
- Защита повторного принятия, отмены и повторного отклика читает наличие матча
  свежим `Match.objects.filter(sparring_response=response).exists()` внутри
  существующих транзакций. Кэш обратной связи не используется для решения
  об изменении данных; порядок блокировок не меняется.
- Проверки Django не отключаются; `SILENCED_SYSTEM_CHECKS` не изменён.

## Миграция и совместимость

`tournaments.0082_sparring_response_one_to_one` меняет только состояние Django
через `SeparateDatabaseAndState`. Уникальное ограничение создано прежней
миграцией `0073_alter_match_sparring_response`; столбец, UNIQUE, внешние ключи,
индексы и данные не меняются. Новая миграция не выполняет DDL или backfill.

Уникальность предварительно проверяется на рабочей БД только чтением.
Миграционный тест проверяет реальный переход с `0081` на `0082` и обратно,
неизменность записей и схемы, отказ при втором матче на тот же отклик,
а также допустимость нескольких матчей с `NULL` вместо отклика.

Старый и новый код используют одинаковую схему БД. При откате достаточно
выпустить прежний Git ref; автоматически откатывать миграции или восстанавливать
дамп поверх настоящей базы не нужно. Старые опубликованные миграции не правились.

## Проверки

Новые тесты находятся в `tests/unit/test_sparring_match_relation.py`,
`tests/integration/test_sparring_match_relation.py` и
`tests/integration/test_sparring_match_relation_migration.py`.

Они проверяют отсутствие `fields.W342` без подавления, обратную связь и админку,
сохранение ссылки в кабинете без N+1, уникальность на уровне БД, `SET_NULL`,
защиту повторных действий и неизменность данных при миграции.
