# Twisted: оценка применимости и предложение, не разрешение на выпуск

## Статус

19 октября 2026. Анализ относится к `aa440e5171dccacc3e505db8a2396c9cf3104245`,
PR [#1](https://github.com/Skifmail/TennisFan/pull/1).
Исторический анализ, **предложение больше не актуально**: пользователь позднее
явно согласовал замену Daphne на Uvicorn. Исключение **не добавлялось**.
Уязвимая цепочка удаляется из зависимостей, а не скрывается от аудитора.
Этот документ не разрешает merge/deployment; актуальные результаты —
в [предрелизном отчёте](onesignal-preflight-2026-10-19.md).

## Подтверждённый результат

На скриншоте нового GitHub Actions run #14 установка runtime/dev прошла, а
`Audit locked runtime dependencies` обнаружил ровно одну уязвимость:
Twisted 26.4.0 / `CVE-2026-106454` (`GHSA-8pqf-f4m5-798g`).
Графа исправленных версий пуста. Docker job `image` прошёл; следующие проверки
задания `checks` не выполнялись, deploy пропущен. Локальные тесты не заменяют эти
пропущенные проверки GitHub.

## Механизм уязвимости

По [официальному advisory](https://github.com/twisted/twisted/security/advisories/GHSA-8pqf-f4m5-798g)
ошибка находится в `twisted.mail.imap4.wildcardToRegexp`. Аутентифицированный клиент
IMAP-сервера может передать специально составленный шаблон LIST/LSUB, вызывающий
чрезмерный backtracking регулярного выражения и блокировку event loop.
Рейтинг автора advisory — Moderate, CVSS 4.3. В записи нет исправленной версии;
на момент проверки PyPI публикует 26.4.0 как последнюю стабильную.

## Свидетельства по исследуемому приложению

- `requirements.lock` содержит Twisted 26.4.0; пакет действительно остаётся уязвимым.
- Daphne указан как ASGI-сервер в Procfile, обоих Compose-файлах и CI.
- `config/asgi.py` маршрутизирует только HTTP и WebSocket; чат запускается через
  `daphne ... config.asgi:application`, а не как почтовый сервер.
- В исследованных Python-файлах `apps/`, `config/`, `scripts/` не обнаружены
  обращения к Twisted IMAP / IMAP4 / LIST / LSUB; в исследованной конфигурации
  Tennison нет запуска IMAP-сервера.
- В новом изолированном dev-окружении загружены Django, ASGI и `daphne.server`.
  `twisted.mail.imap4` при этом не загружен. Результат сохранён локально в
  `/tmp/tennison-push-preflight.WNUW8f/twisted-applicability-20261019.json`.

**Вывод-оценка:** известный путь атаки через IMAP не обнаружен в проверенном
способе запуска Tennison. Это не исправление пакета, не доказательство отсутствия
любых уязвимостей и не инвентаризация всех процессов VPS. Другие приложения,
ручные команды, плагины и будущие изменения не покрыты этой оценкой.

## Предлагаемое решение без замены сервера

Только после явного принятия остаточного риска уполномоченным человеком можно
оформить временное адресное исключение для этой находки. Предлагаемый срок:
до **26 октября 2026, 00:00 UTC**; с этого момента CI должен снова блокировать выпуск.
Истечение срока в CI само по себе не остановит уже работающий сайт.

Ограничения будущей реализации:

1. Только пакет Twisted, версия 26.4.0 и этот CVE/GHSA; не глобальное отключение аудита.
2. Исходный результат сканера сохраняется, исключение явно помечается как принятый
   временный риск. Нельзя показывать «уязвимостей не найдено» при наличии этой находки.
3. Любая другая уязвимость, иная версия пакета, ошибка сканера/сети, некорректный
   отчёт или истечение срока блокируют проверку. Ошибки не маскируются успешным кодом.
4. Предварительно написать тесты для разрешённого точного совпадения, чужого
   пакета/версии/уязвимости, смешанного отчёта, ошибки сканирования и границы срока.
5. Зафиксировать основание, согласование и срок в репозитории. При появлении
   исправленного релиза перейти на него после проверки и удалить исключение.
   Перед добавлением IMAP-функциональности оценка должна быть пересмотрена.
6. После согласованного изменения повторить CI целиком, включая пропущенные ранее
   проверки, и получить отдельное подтверждение перед merge/deployment.

Если временный риск не принят, оставить PR открытым без выпуска: ждать исправленного
релиза либо отдельно согласовать удаление/замену зависимости. Не менять сервер
или audit-политику молча ради зелёного статуса.
